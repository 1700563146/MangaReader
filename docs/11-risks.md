## 2. 高暴露度风险详解

### R-01 / R-02 / R-03 法律与平台

- **判断**：这是项目的根本风险，技术手段只能降低概率，不能消除。
- **已做的结构性缓解**：零内置源、规则数据化、撤销列表、不上架商店、不商用、免责声明四处可见、投诉通道。
- **红线**：一旦被要求下架具体规则或功能，立即执行，不做法律对抗；保留处理记录。
- **观察指标**：投诉数量、平台警告、社区讨论中的「盗版/破解」指控。

### R-04 源生态

- **本质**：源的生命周期由第三方站点决定，工具能做的是**缩短修复时间**。
- **手段**：规则热更新（M5）、健康度可见（M5）、fixture CI（M1）、规则作者激励（贡献指南/致谢）。
- **阈值**：连续 7 天「启用源中健康比例 < 50%」→ 发公告说明、暂停索引推荐、集中修复。
- **长期**：规则仓库独立于主仓库，避免主仓库因规则问题被牵连。

### R-05 恶意规则

- **威胁模型**：规则作者（或篡改者）试图让 App 发起非预期请求、读取本地数据、耗尽资源。
- **控制**：域名白名单、请求方法限制、响应体上限、脚本白名单 + 3s 超时、无文件/设备 API、签名/哈希、撤销。
- **检测**：导入时静态检查（域名、脚本关键字）、运行时审计日志（只记录 host/次数）、用户举报。
- **预案**：撤销全部相关规则 → 发布公告 → 强制刷新索引；极端情况禁用「索引安装」，只允许本地导入。

### R-06 阅读器性能

- **不确定性**：Compose 的 pager + 缩放 + 大图在低端机上的表现需要实测。
- **控制**：M2 决策门、Macrobenchmark、真实设备（含 4GB 内存机型）。
- **预案**：回退 `AndroidView` 画布（1 天工作量，契约不变），不推翻 `ReaderController`/ViewModel。
- **不做**：为性能提前引入两套实现（维护成本更高）。

### R-08 维护可持续性

- **现实**：开源漫画阅读器项目最常见的死因不是技术，而是维护者消失。
- **控制**：文档先行（本项目）、范围克制、自动化（CI/Release/规则 lint）、明确「不承诺时间」。
- **预案**：转「维护模式」（只修安全与严重 bug）、公开招募协作者、提供 fork 指引。

## 4. 复查节奏

- **每周**：CI 状态、issue 分类、源健康度。
- **每里程碑**：风险表更新（新增/关闭）、性能数据、范围调整。
- **每季度**：法律合规复查（依赖许可证、免责声明、投诉记录）、依赖大版本、路线图重排。
